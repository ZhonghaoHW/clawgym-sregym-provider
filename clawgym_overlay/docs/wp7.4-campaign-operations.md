# WP7.4 campaign operations

The provider worker accepts an optional explicit
`--campaign-authorization` document.  When supplied, it verifies the
campaign authorization against the candidate, trial, approval, case, seed and
partition before importing SREGym or starting a lifecycle.  This preserves a
fail-closed boundary for both train and validation purposes while leaving the
historical R0–R1n static entry points unchanged.

The campaign authorization is artifact-only and must be generated by
Evolution Lab.  The provider never scans a workspace, discovers profiles by
name, loads candidate code or changes runtime/tool permissions.  A train
trial uses `partition=train`; rung and R0 regression trials use
`partition=validation`.  All attempts still require the existing claim and
approval chain, recovery and cleanup receipts, and the host Oracle remains the
sole verdict authority.

WP7.4 budgets three train trials and ten validation trials with at most two
infrastructure retries globally.  Bundles and secrets stay outside Git.  ECS
execution is not implied by the presence of this interface; it is admitted
only after local gates and a human execution approval.
